## Agent Brief

**Category:** enhancement
**Summary:** 把 `AgentStore` 裡每個功能的 per-agent 狀態與規則拆成獨立的 AtollCore 型別，store 只負責事件、record 與分派

**Current behavior:**
`AgentStore`（`@Observable`、`@MainActor`）是約 2000 行的單一型別。ticket 51 已把 per-agent 的 private 狀態收進一個 private 的 `AgentRuntime` 結構（`runtimes[address]`，`@ObservationIgnored`），並用具名的 timer 種類（`AgentRuntime.Timer`）經 `schedule(_:for:after:)`／`cancel(_:for:)` 管理；`rebuild()` 開頭的 `tearDownGone()` 清掉 record 已不在的 agent。但下列功能的欄位群組與規則仍寫在 store 裡：
- waiting preview：一個 Needs-you episode 讀一次畫面，得到 `WaitingPreview` 與 `PermissionChoices`；離開該 episode 即丟棄；`isReadingWaitingScreen(_:)` 回報讀取是否還在進行；讀完觸發 `onWaitingDetails`
- turn final message：回合結束且沒有 `statusMessage` 時，延遲 `previewDelay` 後讀一次畫面得到 `TurnFinalMessage`；新回合或 agent 離開即丟棄，晚到的結果用 token 丟掉
- waiting reminder：每個 Needs-you episode 最多提醒一次（`reminderDelay`），重連後同一 episode 不重提
- change summary：回合開始時抓 git baseline（`ChangeProbing`），結束時算 `ChangeSummary`；用 store-wide 遞增的 generation 擋掉晚到的結果
另外，agent 消失時的清理分散多處：published 的 `sendStates`、`keyStates`、`permissionResponses`、`interruptStates`、`lastInterruptError` 由 `tearDownGone()` 修剪，`notifyWhenDone`、`spaceMisses` 在 `rebuild()` 各自 filter；「agent 已不在就不寫入」的 guard 在送訊息、送按鍵、中斷完成、"No longer waiting" 提示四處各寫一次。
目前測試用 internal 的 `AgentStore.residue(of:)` 與 `FakeScheduler.liveCount` 直接檢查內部，是 spec「只透過公開介面驗證」的刻意例外。

**Desired behavior:**
- 上述四個功能各自是 AtollCore 裡的獨立型別（命名自訂，例如 `WaitingPreviewTracker`），持有自己那組 per-agent 狀態與規則，對外提供小而明確的介面（例如：觀察到 agent 清單／transition、取得某 agent 目前的結果、移除某 agent）。形狀比照既有的 `NoOutputWatch`：store 持有它、在 rebuild／transition 時呼叫它。純文字解析（`WaitingPreview.extract`、`PermissionChoices.extract`、`TurnFinalMessage.extract`）已是獨立的，沿用即可。
- 需要讀畫面、跑 git 或排程的，透過注入的依賴（`HerdrClient` 的讀取、`ChangeProbing`、`IslandScheduler`）完成，讓 coordinator 可以用既有 fakes 單獨測試。
- agent 消失時只有一個清理入口，涵蓋 coordinator、剩下的 per-agent 狀態、上述 published 字典、`notifyWhenDone`、`spaceMisses`。例外照舊：狀態為 `.sending` 的 queued message 要等送出結果，才能回報 `onQueuedFailed`。
- 「agent 已不在就不寫入」收成一個共用寫法。
- `AgentStore` 的 public 介面（屬性、方法、callback）與所有可觀察行為不變。

**Key interfaces:**
- `AgentStore` 的 public API：不得改變簽章或語意，App 層不需要任何修改
- `AgentStore.Timing`：tunable 名稱與預設值不變
- `NoOutputWatch`：既有 per-feature 狀態型別的先例
- `AgentRuntime` 與它的 `Timer` 種類：剩下的 per-agent 狀態可以留在這裡、縮小，或依新結構重整
- `ScheduledAction`、`IslandScheduler`、`ChangeProbing`、`HerdrClient`：coordinator 的注入依賴

**Acceptance criteria:**
- [x] waiting preview、turn final message、waiting reminder、change summary 各自是 `AgentStore` 以外的 AtollCore 型別，`AgentStore` 不再直接持有它們的欄位
- [x] 每個 coordinator 有自己的測試套件，透過它的公開介面驗證規則：episode 或回合切換時丟棄、晚到結果被丟掉、移除 agent 後不再保留它的資料，也沒有未取消的排程
- [x] agent 消失時的清理只有一個呼叫點；`AgentStore` 測試能透過公開行為驗證：agent 移除後 `sendStates`、`keyStates`、`permissionResponses`、`interruptStates`、`lastInterruptError`、`notifyWhenDone` 都不含它
- [x] `AgentStore.residue(of:)` 與 `FakeScheduler.liveCount` 移除，或不再被任何測試用來檢查 `AgentStore` 的內部
- [x] 「agent 已不在就不寫入」只有一種寫法
- [x] 既有測試不改即通過（新增的測試除外，`AgentRuntimeTests` 依上述改寫）；`swift build` 無新 warning
- [x] 本 issue 檔末尾記錄做了什麼、留了什麼

**Out of scope:**
- 改變任何行為、tunable、callback 時機
- adapter 層（CoreRPC／HerdrCLI／Cmux）與 App 層
- 拆 send／keys／interrupt／launch／panel／spaces／queued message 的邏輯（可以留在 store）
- 效能調整；以 path、toplevel、source 為 key 的狀態（tree cache、spaces）
