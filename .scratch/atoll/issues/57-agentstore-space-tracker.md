## Agent Brief

**Category:** enhancement
**Summary:** 把 Herdr spaces 的狀態與規則從 `AgentStore` 拆成一個獨立的 AtollCore tracker，store 只負責轉發、在 rebuild 時查詢、在 agent 消失時清理

**Current behavior:**
`AgentStore`（`@Observable`、`@MainActor`）自己持有 Herdr GUI spaces 的全部狀態與規則：
- 可觀察的 `spaces`（Herdr app 目前的 spaces，app 沒開時為空）、`cachedSpaces`（跨 app 關閉與重啟保留，經 `onSpacesCached` 持久化）、`pendingSpaceNames`（沒開 app 時 launch 建的 space 的名稱，經 `onPendingSpaceNamesChanged` 持久化）
- private 的刷新機制：週期 timer（`Timing.spaceRefreshInterval`）、「刷新中又被要求一次」合併成刷新完再跑一次、generation 用來丟掉 app 關閉後晚到的讀取、進行中的 rename id、已為其觸發過一次刷新的未對應 herdr-core terminal
- `herdrAppRunning` 的 `didSet`：開啟時立刻刷新，關閉時作廢進行中的讀取、取消 timer、清空 `spaces` 並重建
- rebuild 時把 herdr-core agent 對應到 space（填 `Agent.spaceID`／`spaceName`），第一次對應不到時觸發一次刷新
- 讀取成功後套用 pending names（rename 成功才移除、失敗下次再試；primary snapshot 到之前不判定孤兒；app 沒顯示、也沒有 live terminal 標著它的 pending name 丟棄）
- `launchSpaces()`：app 開著時讀一次，與 `Timing.launchSpacesTimeout` 競速，失敗或逾時回 offline spaces（`HerdrLabels.spaces(cached:terminals:pendingNames:)`）
- agent 消失時由 `forget` 表清掉它的未對應記錄

52 已把四個 per-agent 功能拆成 `WaitingPreviewTracker`、`FinalMessageTracker`、`WaitingReminderTracker`、`TurnChangeTracker`（internal、`@MainActor final class`、closure 注入、store 持有為 `@ObservationIgnored`），spaces 當時刻意留在 store。

**Desired behavior:**
- 上述 spaces 的狀態與規則（除了可觀察的 `spaces` 本身）由一個 AtollCore 的 internal 型別持有，命名比照既有 tracker（例如 `SpaceTracker`），store 以 `@ObservationIgnored` 持有它
- **觀察策略（已定案）**：`spaces` 仍是 `AgentStore` 上可觀察的 stored property（`public private(set)`），由 tracker 在內容改變時透過 callback 回寫並觸發重建，寫入時機與現在相同（只在內容有變時寫）。不要把 `spaces` 改成轉發到 ignored tracker 的 computed property：`IslandModel`／`Notifier` 透過 SwiftUI 觀察它，改了之後 space 篩選會停止更新，而只靠 fake 的測試抓不到。`cachedSpaces`、`pendingSpaceNames` 不在觀察路徑上，可以轉發給 tracker，但 setter 與兩個 callback 的語意不變（App 啟動時先注入舊值，之後只在值有變時回報）
- tracker 透過注入取得依賴：`HerdrClient` 的 `spaces()`／`renameSpace(id:name:)`、`IslandScheduler`、兩個 tunable，以及 store 提供的 closure（primary source 目前的 terminal 資訊、primary snapshot 是否已到、要求重建）。tracker 不回頭依賴 `AgentStore`
- `herdrAppRunning` 仍是 store 的 public 屬性，變化時通知 tracker
- agent 消失時的清理仍走 `forget` 那張表，原本清未對應記錄的那一行改為呼叫 tracker 的移除
- 所有可觀察行為不變：刷新時機與合併、晚到結果丟棄、讀取失敗保留舊值、pending name 的套用／重試／丟棄、`launchSpaces()` 的競速與 fallback、每個未對應 terminal 只觸發一次刷新

**Key interfaces:**
- `AgentStore` 的 public API 簽章與語意不變：`spaces`、`cachedSpaces`、`onSpacesCached`、`pendingSpaceNames`、`onPendingSpaceNamesChanged`、`refreshSpaces()`、`launchSpaces() async -> [HerdrSpace]`、`herdrAppRunning`。App 層不需要任何修改
- `AgentStore.Timing.spaceRefreshInterval`、`launchSpacesTimeout`：名稱與預設值不變
- `HerdrClient.spaces()`、`renameSpace(id:name:)`、`IslandScheduler`／`ScheduledAction`：tracker 的注入依賴
- `HerdrLabels.spaces(cached:terminals:pendingNames:)`：offline fallback，沿用
- 既有 tracker（`WaitingPreviewTracker` 等）與 store 的 `wireTrackers()`、`forget` 表：形狀的先例

**Acceptance criteria:**
- [x] `AgentStore` 不再直接持有 spaces 的刷新 timer、generation、合併旗標、rename 進行中集合、未對應記錄；這些都在新的 tracker 型別裡
- [x] `AgentStore.spaces` 仍是可觀察的 stored property：有一個測試透過 Observation（`withObservationTracking`）確認 spaces 讀取結果改變時會觸發觀察者，內容沒變時不觸發
- [x] tracker 有自己的測試 suite，只透過它的公開介面與既有 fakes 驗證：刷新中的再次要求會合併成一次後續刷新；app 關閉後晚到的讀取被丟掉；讀取失敗保留上一次的結果；rename 失敗會在下次讀取時重試、成功才移除 pending name；primary snapshot 到之前不丟棄 pending name，之後孤兒被丟棄；`launchSpaces` 逾時回 offline spaces；同一個未對應 terminal 只觸發一次刷新，移除後再出現會重新觸發
- [x] 既有測試不改即通過（含 `SpaceTests`、`OfflineLaunchTests`、`LaunchHistoryTests`、`AgentTeardownTests`）；`make check` 通過，`swift build --build-tests` 無新 warning
- [x] App 層原始碼沒有 diff
- [x] 本 issue 檔末尾記錄做了什麼、留了什麼，以及 `AgentStore.swift` 行數變化

**Out of scope:**
- 改變任何行為、tunable、callback 時機
- `SpaceGrouping`（清單分段、`SpaceFilter`）與 App 層的 space 篩選
- queued message、auto-advance、send／keys／interrupt／launch／panel 的邏輯
- adapter 層；效能調整
