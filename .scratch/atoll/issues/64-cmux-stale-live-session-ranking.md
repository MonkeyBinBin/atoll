# 64: cmux 漏送 `SessionEnd` 時，舊的 live session 蓋過剛結束的新 session

**What to build:** 同一個程序（pid）的多個 session 由 `CmuxSessions.terminals()` 合併成一個 agent，用 `outranks` 決定由誰代表。規則是 live session 永遠贏過正在結束（寬限期內）的 session，兩者都是 live 或都在結束時，才比 `touched` 新舊（ticket 62）。

如果 cmux 漏送某個 session 的 `SessionEnd`，它會一直被當成 live：
1. session A 的 `SessionEnd` 遺失，A 停在 live。
2. 同一程序開了 session B。B 比較新，所以由 B 代表 agent，畫面正確。
3. 在 B 裡執行 `/clear`：B 結束、進入寬限期，A 是 live，所以 A 勝出。agent 的 session id（`SessionHint.idLabel`）、狀態和 transcript 都切回 A 的舊內容，直到新的 session C 開始。

ticket 62 之前，B 一結束就直接消失，A 一樣會勝出；差別是現在這個情況會發生在寬限期內，也就是 `/clear` 的過程中。目前沒有實際觀察到 cmux 漏送 `SessionEnd`，這是看程式碼推導出來的情境。

做法方向：「live 永遠優先」是為了 cmux 重複送的舊 `SessionEnd` 可能晚於新的 `SessionStart` 才到，會讓舊 session 的 `touched` 比較大。ticket 62 後來加了 `endedIDs`，已結束的 session 只接受 `SessionStart`，重複送來的 `SessionEnd` 會直接略過、不更新 `touched`。所以這條規則可能已經不需要，`outranks` 可以回到單純比 `touched`。動手前先確認這點；另一個選項是只有在 live session 的最後一次更新晚於對方的結束時間時，才讓 live 勝出。

  ## Agent Brief

  **Summary:** 同一程序的 session 合併成 agent 時，只依最後更新的新舊決定代表，拿掉「live 永遠優先於正在結束的 session」規則

  **Current behavior:**
  `CmuxSessions.terminals(now:include:)` 把同一個 pid 的 session 合併成一個 agent。決定代表的 `outranks` 規則是 live session 永遠贏過寬限期內正在結束的 session，兩者狀態相同時才比 `touched`。若某個 session（A）的 `SessionEnd` 遺失，A 會一直是 live。之後同一程序的 session B 在 `/clear` 時結束，B 的寬限期內 A 會勝出，agent 的 `SessionHint.idLabel`、狀態與 transcript 都切回 A 的舊內容。

  **Desired behavior:**
  同一 pid 的 session 之間，最後更新（`touched` 最大）的那個代表 agent，不論它是 live 還是在寬限期內。上述情境中，B 的寬限期內 agent 由 B 代表。新的 session C 一開始就由 C 接手，因為 `SessionStart` 會讓 C 成為最新。「live 永遠優先」原本是為了處理 cmux 重複送的舊 `SessionEnd` 晚於新 `SessionStart` 到達，這種重複 hook 現在已經不會更新 `touched`，所以這條規則可以拿掉。

  **Key interfaces:**
  - `CmuxSessions` 內決定同一 agent key 由哪個 session 代表的比較規則（目前是 `outranks`）：改為只比 `touched`，並更新它的 doc comment
  - `CmuxSessions.terminals(now:include:)` 的對外行為：寬限期與 `include` 的過濾不變，只改同一 key 內的選擇
