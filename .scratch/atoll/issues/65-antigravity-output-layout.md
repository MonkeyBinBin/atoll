# 65: Antigravity CLI 的輸出 panel 沒有過濾與對應的上色

**What to build:** Antigravity CLI（`agy`）的 OSC 7501 `app` word 是 `antigravity`（hc 實測），`AgentTool.from(app:)` 把它當成 `.generic`。`OutputFilter.messages` 對 generic 只有 opencode 有 layout，其他一律 `kept = all`，所以 Messages 模式顯示的是整個終端機畫面；`OutputStyling.heuristic` 的規則是照 Claude Code / Codex 寫的，套到 Antigravity 時有落差。

`agy` 1.5.13 的畫面（2026-11-20 在 hc 實測，email 與路徑已去識別化）：

```

   ▄▀▀    ▀▀▄     /path/to/project
  ▄▀▀      ▀▀▄

────────────────────────────────────────────────────────────
> Read README.md and main.go, then change main.go to print "hello atoll" …

○ Thought for 13.3s (The `PATH` environment variable appears standard, …)
● Explored 2 files (README.md, main.go)
● Edited 1 file (main.go)
● Ran 9 commands, killed 1 task (go run . ×2 · export PATH=… · source ~/.zshrc 2>/dev/null || true; w...)
● Explored 1 file (.zshrc) (ctrl+o to expand)

File access
  ⎿  User declined the tool call

────────────────────────────────────────────────────────────
> Stop running commands. Just reply now: …

▸ Thought for 5s, 391 tokens

  Update Summary

  • Updated main.go to print "hello atoll" as requested.
  • Attempted execution with go run ., but the command could not run …

────────────────────────────────────────────────────────────────────────────────── (全寬)
>
────────────────────────────────────────────────────────────────────────────────── (全寬)
? for shortcuts                                                                    auto · Gemini 3.8 Flash · high
```

- 每則使用者訊息上方有一條較短的 `─` rule（60 欄），輸入框則是兩條全寬 rule 夾 `>`。輸入框下方是狀態列：idle 時 `? for shortcuts`，等待回應時 `esc to cancel`，右側是 `auto · <model> · <effort>`。
- 被打斷時輸入框上方會多一行 `⎿  Interrupted · What should Antigravity CLI do instead?`。
- 回覆的 markdown 已經由 `agy` 渲染：標題沒有 `#`、inline code 沒有反引號，只靠 ANSI 色彩區分。
- hc 送出的訊息會顯示成 `> <hc from="t81">…</hc>`。

**過濾（`OutputFilter`）缺口：**
- 啟動列 `❯ agy`、logo banner（`▄▀▀▄` 與右側的版本 / 帳號 / model / 路徑）沒拿掉。`stripBanner` 只認 Claude Code 的 logo 字元開頭的列，而且只在 `claudeMessages` 裡用。
- 輸入框（兩條全寬 rule 與 `>`）和狀態列沒拿掉。版面與 Claude Code 相同，可沿用 `claudeMessagesAboveInput` 的「從最後一對 rule 的上緣切」，但 footer 規則要另外補（`? for shortcuts`、`esc to cancel`、`auto · … · …`）。注意每則使用者訊息上方的短 rule 長度也 ≥ 20，`isRule` 會把它算進去；只有它和輸入框上緣相鄰時才會被誤判，要確認切點選的是輸入框那一對。
- `activityLines` 對 generic 也是 `kept = all`，狀態列與 banner 都算進 no-output 指紋。`Thought for 13.3s` 的計時已經由 `withoutCounters` 處理。

**上色（`OutputStyling.heuristic`）缺口：** hc（`CoreRPCAdapter`）讀回來的是純文字、不帶 `runs`，所以只能走 heuristic。
- `● Explored 2 files (…)`、`● Ran 3 commands (…)` 是工具列，但 `toolCall` regex 要 `Name(` 才會中，目前只有 bullet 加粗。應該是 green bullet、動詞加粗，和 Codex 的 `• Ran` 一致。
- `○ Thought for …`、`▸ Thought for …` 沒有樣式，應該 muted。
- 縮排的 `  • 項目` 沒有 list marker 樣式（目前只有 indent 0 的 `•` 才處理）。
- `> ` 使用者訊息已經是 accent，`⎿` 行已經是 muted，維持不動。
- 標題與 inline code 在純文字畫面裡沒有標記，heuristic 救不回來，不處理；herdr 帶 ANSI 原色時本來就走 `mapped`。

做法方向：在 `OutputFilter` 加 Antigravity layout（依 `app` 判斷，比照 opencode 的分派方式），heuristic 加 Antigravity 的工具列與 thought 列。用上面的實機畫面寫 fixture。

## Agent Brief

**Category:** enhancement
**Summary:** Antigravity CLI（OSC 7501 `app` word `antigravity`）的輸出 panel 在 Messages 模式只顯示對話，no-output 指紋排除畫面框架，heuristic 上色認得它的工具列與 thought 列

**Current behavior:**
`AgentTool.from(app:)` 把 `antigravity` 歸成 `.generic`。`OutputFilter.messages(_:tool:app:)` 對 generic 只有在 `AgentCLI.matching(app:)` 對到 opencode 時才套 layout，其他保留整個畫面，所以 Messages 模式會出現啟動列 `❯ agy`、logo banner、輸入框與狀態列。`OutputFilter.activityFingerprint(_:tool:)` 沒有 `app` 參數，generic 一律以全畫面計算，狀態列與 banner 都算進 no-output 指紋。hc（`CoreRPCAdapter`）讀回來的是不帶 `runs` 的純文字，只會走 `OutputStyling.heuristic`：`● Explored 2 files (…)` 這類工具列不符合 `toolCall`（`Name(`）規則，只有 bullet 加粗；`○`／`▸ Thought for …` 沒有樣式；縮排的 `  • ` 不在 `listMarkerLength` 認得的 marker 裡。

**Desired behavior:**
- **分派**：`app` word 以 `antigravity` 或 `agy` 開頭（大小寫不拘）時使用 Antigravity layout。直接比對 `app`，不要經過 `AgentCLI.catalog`／`AgentCLI.matching(app:)`，也不要把 `agy` 加進 `catalog`。`AgentTool` 不必新增 case。
- **Messages 過濾**：版面與 Claude Code 相同，輸入框是兩條全寬 `─` rule 夾著 `>`，下方是狀態列（idle 時 `? for shortcuts`，等待回應時 `esc to cancel`，右側 `auto · <model> · <effort>`）。從最後一對 rule 的上緣切掉輸入框，再往上剝掉 footer（含被打斷時的 `⎿  Interrupted · What should Antigravity CLI do instead?` 是否保留由 agent 判斷，但不可剝到真正的訊息）。拿掉頂端的 `❯ agy` 啟動列與 logo banner（`▄▀▀▄` 等 block 字元，右側同列帶版本、帳號、model、路徑）。每則使用者訊息上方約 60 欄的短 `─` rule 與訊息本身保留；`isRule` 的門檻是 ≥ 20 字元，切點必須落在輸入框那一對，不能落在短 rule 上。
- **退回**：找不到靠近底部的輸入框時（Settings 等全螢幕畫面），維持現在的行為，回傳 cleaned 全畫面，不可變成空白。
- **no-output 指紋**：`activityFingerprint` 能拿到 agent 的 `app`（簽名加上 `app: String?`，維持既有呼叫相容或一併更新 `AgentStore` 的 no-output 檢查），Antigravity 的指紋排除 banner、輸入框與狀態列。
- **heuristic 上色**（不改 `OutputStyling.runs(shown:source:)` 的簽名，規則不分 tool）：
  - 行首（indent 0）`● <Verb> <數字> <名詞>…`（例如 `● Explored 2 files (…)`、`● Edited 1 file (…)`、`● Ran 9 commands, killed 1 task (…)`）：green bullet，動詞加粗，與 Codex 的 `• Ran` 一致。pattern 要收窄到「動詞後接數字」，不能讓 Claude Code 的一般回覆 bullet（例如 `● Updated the README…`）變成工具列。
  - `○ Thought for …` 與 `▸ Thought for …`：整列 muted。
  - 縮排的 `• 項目`：bullet 套 list marker 樣式。
  - `> ` 使用者訊息（accent）與 `⎿` 列（muted）維持現狀。標題與 inline code 在純文字裡沒有標記，不處理。

**Key interfaces:**
- `OutputFilter.messages(_:tool:app:)`：generic 分支多一條 Antigravity layout，與 opencode 的分派並列。
- `OutputFilter.activityFingerprint(_:tool:)` / `activityLines`：需要 `app` 才能分派 Antigravity。
- `OutputStyling.heuristic(_:)`、`listMarkerLength(_:)`：新增上述規則。
- 可沿用 Claude Code 的 `claudeMessagesAboveInput` 切法與 `stripBanner` 的 block 字元偵測，但 footer 規則與 banner 判斷要能處理 Antigravity 的版面（banner 前多一列 `❯ agy`，logo 列右側帶文字）。
