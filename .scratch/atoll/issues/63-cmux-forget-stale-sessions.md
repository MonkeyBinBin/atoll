# 63: cmux 從沒結束的 session 與相關快取不會被清除

**What to build:** `CmuxSessions` 只在 session 收到 `SessionEnd`、過了寬限期之後才從 `sessions` 移除（`prune`，ticket 62）。沒有送 `SessionEnd` 就消失的 session（Claude Code crash、`kill -9`、關掉 surface 時 hook 沒跑完）會一直留在 `sessions`，直到 cmux boot 換掉。畫面上不會出錯，因為 adapter 的 `include`（`CmuxAdapter.currentTerminals`）會用 `ProcessInspector.isAlive` 濾掉已結束的 pid，但以下資料都只會增加：
- `sessions`：從沒結束的 session。
- `endedIDs`：已結束的 session id（ticket 62 為了擋下晚到的重複 hook 而加，只在 boot 換掉時清空）。
- `CmuxAdapter` 的 `ownership`（pid → 是否屬於 herdr）：每個看過的 pid 都留著。

每個 hook 和每 3 秒的 tick 都會走過整個 `sessions`，`prune` 也會在每個 hook 重建整個 dictionary，就算沒有東西要移除。cmux 長時間不重開、反覆開關 agent 時，量會慢慢累積。影響目前只有記憶體與每次 publish 的成本，畫面行為正確。

做法方向：
- 程序已經不在的 session 也要移除。`CmuxSessions` 是 pure 的，pid 是否存活由 adapter 判斷。可以讓 adapter 傳入存活判斷，或由 `CmuxSessions` 提供移除指定 session 的方法。
- `endedIDs` 和 `ownership` 跟著對應的 session 或 pid 一起清掉。注意：`endedIDs` 是用來擋晚到的重複 hook 的，清掉的時機至少要晚於寬限期。
- `prune` 沒有東西要移除時，不重建 dictionary。
